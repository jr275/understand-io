# Languages: English and Brazilian Portuguese

English is the default. Brazilian Portuguese is the second language. There is one application: the language is data, not a copy of the product.

## Where things live

| What | Where |
| --- | --- |
| The two languages and their codes | `src/lib/seo/site.ts` (`LOCALES`), re-exported by `src/i18n/config.ts` |
| Messages | `src/i18n/messages/en.ts` (source of truth), `pt-BR.ts` (must have exactly the same keys; the compiler enforces it) |
| Using a message | client: `const t = useT()`; server: `const t = await getT()`; API routes: `requestT(req)`; then `t("landing.heroAsk")`, `t("topbar.shelved", { n })` |
| Plurals | a message of the form `{ one, other }` takes `{n}`; the language's own `Intl.PluralRules` choose (Portuguese counts 0 as singular) |
| Dates, numbers, currency, relative time, lists | `useI18n().fmt` or `src/i18n/format.ts`, never by hand |
| Which language a request is in | `src/i18n/server.ts` (`resolveLocale`) |
| Addresses and the `/pt-BR` routing | `src/proxy.ts`, `src/i18n/config.ts` (`localePath`, `splitLocalePath`) |
| The switcher | `src/components/chrome/LanguageSwitcher.tsx` |

## How a language is chosen

1. The address: `/pt-BR/...` is Portuguese (the proxy rewrites it to the same page and sets a request header). English addresses never change.
2. For the app's own pages (library, reader): the reader's saved choice (a cookie, set only when they choose), then the browser's Accept-Language.
3. For pages search engines index (landing, learn, legal): **only the address**, so a crawler and a reader see the same thing at one URL. A reader who chose Portuguese and arrives at an English indexed address is redirected; a crawler has no cookie and is never moved.

Switching on the app's pages changes the words in place (`router.refresh()`); the document, scroll position, highlights and open panels are kept. Switching on an indexed page loads the other address (the router treats the two languages of one route as one page).

## SEO

`html lang`, localized title and description, `og:locale`, canonical, `hreflang` and `x-default` are produced per page. An alternate is declared **only** for a page that exists in both languages (the landing page and the legal texts); the learn article and the sample texts are English only and declare none. The sitemap lists both addresses of a bilingual page with its alternates.

## The assistant

The interface language is the default answer language, whatever the language of the text or of the question. A request for another language in the reader's own words wins ("answer in Spanish", "responda em inglês"). Summaries, concepts and questions follow the interface language unless an output language was chosen. Quotes from the text stay in the text's language.

## Adding or changing text

1. Add the key to `en.ts` and `pt-BR.ts` in the same place. Use placeholders for every variable part; never build a sentence by joining pieces.
2. `pnpm test tests/unit/i18nCoverage.test.ts` checks parity, placeholders and that Portuguese is not the English text.
3. A component that no longer carries hard-coded text must leave `tests/unit/i18nPending.json`; the test fails if a listed file is clean or if an unlisted file gains a hard-coded sentence. `I18N_WRITE_PENDING=1 pnpm test tests/unit/i18nCoverage.test.ts` rewrites the list from what is found now (to see the backlog, never to hide a new one).
